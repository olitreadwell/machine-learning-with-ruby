# What this revival changed

`arbox/machine-learning-with-ruby` last took a commit in December 2024. This
fork runs the list on the gate from
<https://github.com/olitreadwell/awesome-list-template>, pinned to engine
revision `0d13482`.

## The entry shape

Every entry in this list carried its description on the indented line below the
link, with the separator left dangling at the end of the first line:

```markdown
- [rumale](https://github.com/yoshoku/rumale) -
  Machine Learning toolkit in Ruby with a wide range of algorithms.
```

The engine and the linter both read a bullet as one line, so 65 of those
descriptions moved up to the bullet they belong to. No word changed. Another 49
entries already had their description on the bullet line and were missing the
` - ` separator, which is in place now. 45 descriptions were missing the closing
period.

Entries that ended with a dependency marker, as in

```markdown
- [classifier-reborn](https://github.com/jekyll/classifier-reborn) - General classifier module to allow Bayesian and other types of classifications.
  <sup>[[dep: GLS](#gls)]</sup>
```

took one mechanical repair: the marker joins the bullet line before the final
period and its outer brackets are escaped, because an unescaped `[[dep: GLS]]`
reads as a reference link. 34 entries had that shape.

## The readme

- The file carried a second table of contents between `<!-- toc -->` and
  `<!-- tocstop -->`, generated by a tool. It listed the same headings as the
  one the engine keeps, and two links to one anchor is a duplicate link to the
  linter. It is gone, and `make toc` rebuilt the remaining Contents block.
- The heading read `# Awesome Machine Learning with Ruby` and the header image
  above it was centred, which the linter counts as a second heading. The
  heading is `# Awesome Machine Learning With Ruby` and the image is no longer
  centred.
- The readme ended with a `## License` section. The linter forbids one, so the
  heading and its text are gone. `LICENSE` carries the same CC0 1.0 deed.
- `[The Ruby Science Foundation][sciruby]` and four other reference links used
  a full label where the link text and the label are the same, which the linter
  wants collapsed. One reference link pointed at `[gls]` while the definition
  is `[gsl]`, so the link never resolved. The unused `change-pr` definition is
  gone.
- The three sibling lists at the top were wrapped in brackets, which reads as a
  reference link to a definition that does not exist.

## Entries

- The seven host entries in Related Resources began with an `<a name>...</a>`
  anchor, which the linter reads as an entry with no link. The anchor sits after
  the separator now, so the anchor still works for the dependency markers and
  the entry reads as an entry.
- Two descriptions opened by repeating the item name, `Handwritten Digits
  Recognition` and `iRuby`. The repeated name is gone.
- `simple_ga` was listed in Machine Learning Libraries and again in Projects and
  Code Examples with the same URL and the same kind of description. The second
  copy is gone.
- Five pages were linked more than once, and the linter fails every occurrence
  of a repeated link. Three talks by Matthew Kirk, two by Ilya Grigorik, two by
  Kenta Murata, and one of the two RubyThursday episodes now carry their
  video, slides, or post link in the entry position, with the speaker's name as
  plain text. The talk by Marc Berszick pointed at an empty URL for the speaker,
  so the article he wrote holds that link and the marker keeps its label. The
  intro paragraph no longer links the community's Twitter account, because the
  Community section lists it.

Left alone:

- Every description from upstream is the words upstream wrote. The pass moved
  punctuation, link targets, and line breaks, nothing more.
- 21 entries are a link and no description. The gate warns about them and
  `tests/test_readme.py` holds that count.
- Three spell-check warnings stay: `Scikit-Learn`, `tensorflow`, and
  `Tensorflow`, each one the spelling the entry itself chose.

## Links kept on http

`gnuplot.info` and `sciruby.com` answer on http and not on https, so both sit
in `links.allowlist`. `graphviz.org` and `r-project.org` answered on https and
moved there.

## Tooling

- `pyproject.toml` pins the engine, `Makefile` carries the engine targets, and
  `AGENTS.md` describes the layout for whoever works here next.
- `github-stats.json` records stars and last push for the 71 GitHub entries,
  and `exports/` holds the list as JSON, NDJSON, and CSV.
- `.githooks/pre-commit` and `.githooks/pre-push` run the gate. Install them
  with `make hooks-install`.
- `make check` covers the list rules, the Contents block, the stats snapshot,
  the exports, and the tests. `tests/test_readme.py` holds the URL repeats to
  what `links.allowlist` records, rather than failing on any repeat at all.
- Upstream ships `Gemfile`, `Rakefile`, and `.travis.yml` from its Ruby tooling
  days. They are untouched and unused by the gate.
- `.gitignore` carried `*json`, which would keep the stats snapshot and two of
  the three exports out of the repository. Those four files are un-ignored,
  because `make check` reads them.
